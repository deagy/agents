# Official MCP Python SDK for roster/orchestration/mcp/dispatch_server.py and
# roster/orchestration/mcp/gitlab_server.py (the GitLab-evidence MCP server).
# Optional: neither dispatch_core.py nor gitlab_core.py (the actual
# dispatch/authorization/isolation logic, and the GitLab request/retry/
# confirmation-gate logic, respectively) depends on this package -- both are
# fully unit-testable without it, matching
# roster/shared/requirements-validation.txt's PyYAML pattern -- only running
# dispatch_server.py or gitlab_server.py requires this, and each fails closed
# with an install pointer (not a silent no-op) if it's missing.
#
# Stdio transport only. Do not install an extra that pulls in a networked
# transport (e.g. `mcp[cli]` brings in starlette/uvicorn for HTTP/SSE
# serving, which this component does not use and must not depend on) --
# install the bare `mcp` package.
#
# The pin below must stay identical to `pyproject.toml`'s `[project.
# optional-dependencies] mcp` extra -- they install the same package for the
# same two servers, and a pip/pipx install resolves the extra while a
# checkout install resolves this file. They drifted once already (PR #113
# bumped 1.2.1 -> 2.0.0 in pyproject.toml only, leaving this file two minor
# versions behind for anyone installing from a checkout); bump both together
# or not at all. Do not silently widen this to an unpinned or range spec.
#
# TODO(2026-07-25, M-2, tracked follow-up -- see security review of the MCP
# dispatch server): this pin is version-only, not hash-pinned. Add a
# `--hash=sha256:...` pin (and pin/hash its transitive dependencies) once
# this sandbox has network/package access to resolve and verify the actual
# published artifact hashes from PyPI. Not done here because doing so
# without being able to verify the hash against the real published package
# would just be fabricating a hash, which is worse than no hash.
mcp==2.0.0
